# 测试病例 02 · 年轻男性「胃疼」——不该报的就不报（阴性对照）

> 用途：验证 TriageOS 的**分辨力**——同一个"胃疼"，年轻小伙子就必须放回候诊区，
> 不能见痛就报心梗。这是病例 01 的镜像：一个该抓，一个该放。
> 建议演示时长 3 分钟；可与病例 01 连起来做"同一症状，两个结局"的对照。

---

## 一、病例（可以直接念）

**陈昊，男，24 岁。**

昨天晚上朋友聚会，吃烧烤、喝啤酒。今天早上开始胃疼、烧心，有点恶心，没吐。

无黑便、无呕血、无发热。平时身体好。

生命体征：血压 **118/74**，心率 **82**，呼吸 16，体温 36.8℃，血氧 99%。

## 三、预期结果（首次分诊）

### ① 信息采集与多模态

- 标题：`把口语规范为 2 个标准术语`
- 翻译对照：

| 患者原话 | 标准术语 |
|---|---|
| 今天早上胃疼 | 上腹痛 |
| 有点恶心想吐 | 呕吐 |

### ② 红旗风险预警（**本病例的考点**）

- 标题：`未见致命性红旗：已排查 18 类致命急症`
- **红旗列表为空** —— 这就是要验证的东西：年轻 + 无危险因素 + 无冷汗 + 生命体征正常，
  哪怕主诉是"胃疼"，也**不该**触发心梗/夹层。

### ③ 分级裁判

- **ESI 3 级**（紧急候诊，30 分钟内）
- 预计资源 3 项：实验室检查、影像学、静脉补液

> 诚实说明：ESI 3 是这 3 项资源推出来的；其中"恶心 → 静脉补液"是偏保守的估计，
> 真实 ESI 由资源条数决定，本系统宁可给 3 级也不往 4 级压。

### ④ 交叉核验质控

- 结论：`质控通过：裁判 ESI 3 未被推翻（安全底线 5 级）`
- **八项检查全过，无任何扣分**（生命体征齐全、过敏史已记、无级别矛盾）

### ⑤ 动态候诊监测

- `已纳入动态监测：每 30 分钟复评，队列第 1 位`

### ⑥ 医患沟通安抚

- 常规版以 3 级话术开场：`你的分级是 3 级——紧急，医生会在 30 分钟内接诊…`

### 工单（Human-in-the-loop）

- **0 张** —— 这是本病例最硬的一条断言：不该打扰医生的时候，一个工单都不能弹。

## 四、和病例 01 差在哪（同一症状，两个结局）

| 维度 | 病例 02（本病例） | 病例 01 |
|---|---|---|
| 年龄 | **24** | **68** |
| 基础病 | 无 | 糖尿病、高血压、吸烟 |
| 冷汗 | **无** | **有** |
| 肌钙蛋白 | 未查 | 0.15 ↑ |
| 结局 | 0 红旗 · ESI 3 · 0 工单 | 心梗 0.98 · ESI 2 · P0 工单 |

> 决定去抢救区还是候诊区的，不是"胃疼"这个词，而是**年龄 + 危险因素 + 大汗 + 化验**。

---

## 五、变一个词，结果立刻翻（分辨力验证）

以下三条都在本机实测过（括号里是实际跑出来的结果）：

| 改动 | 实测结果 |
|---|---|
| 主诉加一句"**还出了一身冷汗**" | 心梗 **0.70**，ESI 2，P0 工单 |
| "胃疼"改成"**突然疼得像撕开一样**" | 主动脉夹层 **0.85**，ESI 2，P0 工单 |
| 年龄改 68 + 既往史加糖尿病 + 冷汗 | 心梗 0.85 + 老年急腹症软提示 0.60，ESI 2 |

这一节是给评委看的：同一个模板，**只动一个词**，系统就换一副面孔——
说明它不是在死记"胃疼 = 没事"，而是在读症状组合。

## 八、对不上时怎么排查

| 现象 | 最可能的原因 |
|---|---|
| ② 出了红旗 | 既往史误填了"糖尿病/高血压"，或主诉带了"冷汗/撕裂/大汗"等关键词 |
| 给了 2 级 | 同上——先看红旗卡片里命中了哪些证据 |
| 给了 4 级 | 说明"恶心→补液"这条资源没被算上（词典改了"恶心想吐"） |
| 工单不是 0 | 检查是否手滑点了「呼叫医生接管」或「填充候诊队列」 |

## 九、建议的演示组合（两个病例连讲）

1. 先跑**病例 02**（年轻胃疼）→ 0 红旗、ESI 3、0 工单：证明系统不瞎报；
2. 现场把年龄改成 68、加糖尿病和"冷汗" → 心梗 0.98、ESI 2、P0：证明系统也不漏；
3. 一句话收尾：**"该抓的抓得住，该放的放得走。"**
